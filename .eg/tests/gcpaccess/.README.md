### gcp access test.

verifies a workload has working gcp application default credentials with no/minimal user setup, however they were provided.
no token or secret is printed, only whether a token could be minted.

paths:

- `eg compute upload --gcp-auto`, and the scheduled and event driven workloads of the control plane: the runner issues credentials through workload identity federation, they set `EG_GCP_WORKLOAD_IDENTITY_ENABLED=true` in their environment. the control plane does so for workloads with a `gcpsm://` secret. needs a gcp identity connection labelled with the account id (`eg gcp wif ls`) and a runner daemon with gcp federation support.
- `eg compute local --gcp-auto` (or `--gcp`): your own application default credentials.

```bash
eg compute upload --gcp-auto tests/gcpaccess
eg compute local --gcp-auto tests/gcpaccess
```

expected output in the workload's logs: `gcp access ok`.
a failure means the workload has no working credentials: it did not enable them, the account has no connection, or the credentials are not valid for gcp.
